## 2024-09-02 - UI Refactor
**Learning:** Found several inconsistent and hard-to-maintain hardcoded modifiers on `HordeButton` and `HordeSecondaryButton` uses across screens like `MainMenuScreen`, `PauseScreen`, and `GameOverScreen`. Specifically, many of these buttons have `Modifier.widthIn(max = 350.dp).fillMaxWidth(0.9f)` or similar layout definitions inline.
**Action:** The shared components `HordeButton` and `HordeSecondaryButton` in `HordeUI.kt` should define their own default layout constraints (like a sensible `widthIn(max = 350.dp)`) if they are the primary action buttons, but allow callers to override them via the `modifier` parameter, or at least keep them consistent. Given the specific instruction in memory: "avoid hardcoding layout constraints like `.fillMaxWidth()` inside the base component; instead, allow callers to pass them via the modifier parameter", I will simply leave them to be passed in. However, to ensure consistency and clean up the call sites, I can extract common layouts into styled buttons or clean up the calls.
## 2024-09-02 - Customizing Compose Toggles\n**Learning:** When building custom draggable or toggleable UI elements in Jetpack Compose, directly translating Material3 defaults into Box/pointerInput logic requires care. Specifically, drag offset must be tracked locally during gesture sweeps (not by repeatedly appending to a hoisted state, which lags behind events), and 'toggleable' is preferable to 'clickable' for correct accessibility. Missing Role.Slider and improper state capture can completely break the component.\n**Action:** Use Modifier.toggleable with Role.Switch, and local var accumulators in detectDragGestures for sliders.
## 2024-09-01 - Consolidate UI Interaction Logic
**Learning:** Found multiple duplicate implementations of button interaction logic (`MutableInteractionSource`, `isPressed`, `isHovered`, scale animations, and sound triggers) across `HordeUI.kt` (`HordeButton`, `HordeSecondaryButton`, `HordeItemCard`, etc.). Leaving interactive visual states duplicated creates inconsistencies and makes it difficult to adjust the game's overall "feel" (like bounce stiffness or sound behavior).
**Action:** Extracted the entire interaction pattern into a reusable Compose `Modifier.hordeInteractive()`. Replaced the repetitive code in `HordeUI.kt` with this shared modifier. Whenever possible, visual interaction states (hover, press, disable) should be encapsulated in a modifier rather than rebuilt in every button variant.
## 2024-05-19 - Standardized Typography Usage
**Learning:** `HordeTypography` was available in `Theme.kt`, but many UI components and screens still manually hardcoded `fontSize`, `fontWeight`, and `color` directly onto `Text` composables, or overrode them using `.copy(...)`. This fragmented the design system and made it difficult to adjust font sizes universally across the app.
**Action:** Removed manual `fontSize` and `.copy(...)` styling throughout the UI (menus, HUD, settings, game-over screens). Applied explicit `HordeTypography` styles (e.g. `Title`, `Header`, `SubHeader`, `Body`, `Label`, `Value`, `Button`). Kept manual `color` attributes strictly as top-level overrides when dynamic (like coloring stats or buttons based on status).
## 2024-09-02 - Modifier consistency
**Learning:** Found several scattered instances of raw `Modifier.clickable` that manually managed `isPressed` states and handled their own scale animations, leading to inconsistent visual behavior and missed state resets (e.g. `LevelUpScreen.kt`).
**Action:** Always leverage the unified `Modifier.hordeInteractive()` which handles safe state tracking, bounce animations, and standard sound effects out of the box.
